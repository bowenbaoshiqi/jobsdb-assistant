# v0.6.0 Closed-Loop Applications Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a resumable foreground workflow that renders layout-safe v5 tailored resumes, reviews them, replaces all JobsDB resumes with the approved job-specific file, and completes confirmed Quick Apply or manual Apply handoff.

**Architecture:** Python and SQLite own durable state. AI returns only three structured resume sections and a cover letter; a deterministic PDF renderer and validator preserve the v5 frozen region. A serial worker prepares applications, a remote resume manager owns JobsDB document replacement, and the existing apply state machine receives an immutable application-material context.

**Tech Stack:** Python 3.11+, Pydantic 2, SQLite, FastAPI, Playwright ports, PyMuPDF (`pymupdf`), pytest, pytest-asyncio, Playwright E2E, uv.

## Global Constraints

- v0.6 uses Bowen Bao resume v5 as its only source template; the PDF remains private and is never committed.
- AI may change only `Professional Summary`, exactly four `Career Highlights`, and exactly three `Core Competencies`.
- `Work Experience` and every later section are textually and geometrically frozen.
- Font size, line height, page count, and the frozen-section start position cannot change.
- Every Quick Apply includes the approved tailored PDF and approved 100-300 word English cover letter.
- Missing or unverifiable material pauses for human intervention; it never falls back to the default resume or no cover letter.
- All remote JobsDB resumes, including the default, may be deleted before each serial application.
- Submit requires a separate user confirmation after Review.
- Apply roles open the JobsDB detail page and expose materials for manual use; external sites are never automated.
- Fork repositories remain pinned and unmodified.
- Dashboard remains Simplified Chinese and refreshes only on user action.
- Development is TDD with unit, integration, browser E2E, privacy, and live-manual gates.

## File Structure

New focused modules:

- `src/materials/template.py`: v5 geometry and structured section contracts.
- `src/materials/pdf_renderer.py`: deterministic local redraw of allowed regions.
- `src/materials/pdf_validator.py`: frozen-region, geometry, size, and extraction checks.
- `src/domain/application_execution.py`: application lifecycle and immutable identity.
- `src/storage/application_execution_repository.py`: durable transitions and idempotency.
- `src/application/foreground_worker.py`: serial resumable task dispatcher.
- `src/jobsdb/resumes.py`: remote delete-all, upload, and exact-name verification.
- `src/jobsdb/apply/context.py`: immutable resume and cover-letter context for handlers.
- `src/application/execute_application.py`: preparation, Review boundary, confirmation, and handoff.
- `src/storage/v06_migration.py`: additive v0.6 schema migration.

Existing files are extended only at their established seams: material adapter,
material service, apply step handlers, runtime factories, Dashboard routes and
UI, skill instructions, README, version, and tests.
