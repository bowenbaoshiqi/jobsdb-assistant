# v0.5.0 Tailored Materials Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate, preview, version, review, approve, reject, and regenerate one immutable English CV PDF and English cover letter per selected JobsDB job without submitting applications.

**Architecture:** Extend the existing checkpoint-based Agent integration with a pinned `ApplicationMaterialAdapter`. Python owns task identity, orchestration, persistence, artifact validation, hashing, review events, and Dashboard APIs; the active CC/Codex Agent owns AI generation using the pinned application-material fork. Material files remain private under `workspace/`, while SQLite stores durable identities, statuses, hashes, and audit data.

**Tech Stack:** Python 3.11+, Pydantic, SQLite migrations, FastAPI, vanilla JavaScript, pytest, Playwright, uv, Ruff.

## Global Constraints

- v0.5.0 never submits a JobsDB application.
- Selecting N jobs creates N independent material tasks and N independent material packages.
- Each package contains one readable English CV PDF and one 100–300-word English cover letter.
- Reviewer and ATS findings are advisory and never block approval.
- Factual findings create a warning but may be explicitly overridden by the user.
- Regeneration creates version N+1 and never mutates prior versions.
- Exactly one package version per job may be current-approved for a future execution release.
- Candidate data, JDs, tasks, PDFs, cover letters, feedback, and checks remain in ignored private paths.
- No AI provider or API key is added; the active CC/Codex session performs Agent work.
- The pinned AI Job Search fork is consumed through an adapter and is never modified.
- Existing default-CV Quick Apply and manual Apply behavior remains unchanged.
- Production changes follow paired RED/GREEN commits.

## File Structure

- `src/storage/v05_migration.py`: forward-only v0.5 material tables and constraints.
- `src/storage/material_repository.py`: durable task, version, approval, and review-event persistence.
- `src/adapters/application_material.py`: pinned AI Job Search task/result contract and identity validation.
- `src/application/generate_materials.py`: batch planning, checkpoint submission, artifact validation, hashing, and regeneration.
- `src/application/runtime.py`: constructs the v0.5 adapter and generation service from the pinned manifest.
- `src/dashboard/material_service.py`: safe Dashboard commands for batches and review decisions.
- `src/dashboard/material_routes.py`: material APIs and safe private PDF serving.
- `src/dashboard/material_schemas.py`: Dashboard material request/response models.
- `src/dashboard/templates/material.html`: local material preview page.
- `src/dashboard/static/material.js`: preview, copy, approve, reject, and regenerate interaction.
- `src/dashboard/static/material.css`: material preview layout.
- `src/dashboard/query_service.py`: adds latest material state/actions to job cards.
- `src/dashboard/static/dashboard.js`: batch generation and material-status actions.
- `tests/manual/jobsdb_live/`: versioned, non-collected real-site diagnostics and safety README.
- `docs/testing/2026-07-27-v0.5.0-tailored-materials.tdd.md`: release evidence.
