# v0.4.0 Review Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local review Dashboard that exposes truthful Career Ops A-F scoring, persists jobs selected for later materials, and invokes the existing single-job Quick Apply flow with the JobsDB default CV and no cover letter.

**Architecture:** Add a FastAPI/Jinja2 presentation layer inside the main process. Keep SQLite access behind focused repositories, compose a read model from current jobs/evaluations/Profile/selection/application state, and guard the existing `Orchestrator.run(job_ids=[...])` entry with a durable, idempotent single-execution service.

**Tech Stack:** Python 3.9+, SQLite, Pydantic 2, FastAPI, Uvicorn, Jinja2, Vanilla JavaScript/CSS, Typer, pytest, Playwright, uv.

## Global Constraints

- Bind the Dashboard only to `127.0.0.1`.
- Do not enable remote CORS.
- Do not modify either pinned fork or its commit.
- Do not recalculate or extend Career Ops scoring.
- Do not manufacture per-Profile-requirement verdicts.
- A Quick Apply direct submission uses `jobsdb_default` and `none`.
- Apply jobs must never enter browser automation.
- Permit only one active direct-application task.
- Preserve existing rate limits, application history, and browser state machine.
- Do not log or return credentials, cookies, environment values, browser-profile contents, or full candidate source files.
- Use RED, GREEN, REFACTOR checkpoints and keep overall coverage at or above 80%.
- Do not edit or commit the user-owned untracked `scripts/probe_*.py` and `scripts/test_cover_click.py` files.

## User Journeys

1. As a candidate, I can inspect current scored jobs and their persisted A-F findings/evidence so I understand why each score exists.
2. As a candidate, I can include unscored jobs and see `Pending evaluation` rather than an invented score.
3. As a candidate, I can filter jobs and retain those filters after refresh.
4. As a candidate, I can select jobs for later materials and have that state survive restart.
5. As a candidate, I can open the authoritative JobsDB source role.
6. As a candidate, I can confirm one Quick Apply submission using the JobsDB default CV and no cover letter.
7. As a candidate, I cannot accidentally automate an Apply role, duplicate a submission, or run two browser application tasks concurrently.
8. As an operator, I can install, diagnose, start, and stop the local-only service with documented commands.

```python
def add_v04_schema(conn: sqlite3.Connection) -> None:
    conn.executescript("""
        CREATE TABLE job_selections (
            job_id TEXT PRIMARY KEY REFERENCES jobs(id),
            status TEXT NOT NULL CHECK(status = 'waiting_for_materials'),
            selected_at TEXT NOT NULL,
            updated_at TEXT NOT NULL
        );
        CREATE TABLE dashboard_application_tasks (
            id TEXT PRIMARY KEY,
            job_id TEXT NOT NULL REFERENCES jobs(id),
            status TEXT NOT NULL,
            resume_mode TEXT NOT NULL CHECK(resume_mode = 'jobsdb_default'),
            cover_letter_mode TEXT NOT NULL CHECK(cover_letter_mode = 'none'),
            session_id TEXT,
            error_message TEXT,
            screenshot_path TEXT,
            created_at TEXT NOT NULL,
            updated_at TEXT NOT NULL
        );
        CREATE UNIQUE INDEX idx_dashboard_one_active_application
        ON dashboard_application_tasks((1)) WHERE status = 'applying';
    """)
```
