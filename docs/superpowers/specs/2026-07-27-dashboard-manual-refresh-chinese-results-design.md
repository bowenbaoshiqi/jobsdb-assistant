# Dashboard 手动刷新与中文评分结果设计

## 目标

解决 Dashboard 自动轮询导致职位列表持续重建和页面闪烁的问题，并让评分结果区域完整使用中文展示。

## 交互设计

- Dashboard 不再自动轮询评分进度或职位列表。
- 页面提供“刷新评分结果”按钮。
- 用户点击按钮后，前端并行请求评分进度和当前筛选条件下的职位数据。
- 刷新期间按钮显示“刷新中…”并禁用，避免重复请求。
- 请求完成后恢复按钮，并显示最近刷新结果；请求失败时保留当前页面内容并显示错误。
- 用户修改筛选条件时仍立即重新加载职位列表，这不属于后台自动刷新。

## 中文评分结果

- Dashboard 的职位建议、匹配优势、能力缺口、求职风险、A–F 维度标题、评分结论和依据均显示中文。
- Career Ops 原始评分记录及其英文契约保持不变，不修改 fork 或持久化模型。
- jobsdb-assistant 在展示边界提供中文字段：
  - 固定的 A–F 维度标题和 recommendation 枚举使用确定性映射。
  - Agent 生成的新评分通过任务提示明确要求中文 findings、evidence、strengths、gaps 和 risks。
  - 已存在的英文评分通过 jobsdb-assistant 自己的中文展示投影转换，数据库原文不被覆盖。
- 无法可靠翻译的自由文本不得伪造含义；展示投影应保留原始证据语义。

## 数据流

1. 页面首次加载时请求一次职位数据和评分进度。
2. 此后不执行定时器。
3. 用户点击“刷新评分结果”：
   - 请求 `/api/evaluation-progress`；
   - 请求 `/api/jobs`，保留当前 URL 筛选参数；
   - 成功后更新进度区、汇总数字和职位卡片；
   - 失败时保留旧数据并显示错误。
4. 所有实际评分、校验和持久化仍走现有 Python workflow。

## 错误处理

- 单次刷新失败不清空已显示的职位卡片。
- 按钮在 `finally` 阶段恢复可用。
- 进度请求和职位请求分别报告错误，避免一个接口失败导致另一部分数据消失。

## 测试

- JavaScript/浏览器测试验证页面不存在自动刷新定时器。
- 浏览器测试验证等待超过原轮询周期后，职位列表不会被替换。
- 浏览器测试验证点击刷新按钮会更新进度和职位数据。
- 集成测试验证页面包含中文刷新入口。
- 展示投影单元测试覆盖 A–F 标题、建议、优势、缺口、风险及现有英文结果的中文输出。
- 回归测试验证筛选、勾选和投递按钮行为不受影响。

## 非目标

- 不引入 WebSocket、SSE 或复杂的增量 DOM diff。
- 不修改 Career Ops fork。
- 不修改评分算法或 A–F 分数。
- 不触发自动投递、简历改写或求职信生成。
