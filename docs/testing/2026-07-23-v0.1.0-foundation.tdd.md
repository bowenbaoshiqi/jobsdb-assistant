same test and lint commands GREEN.

## Task 6 — Deterministic 80% Coverage Gate

### RED

- Changed the configured gate from 60% line coverage to 80% line+branch coverage.
- Command:
  `uv run pytest -m 'not e2e' --cov=src --cov-branch
  --cov-report=term-missing`
- Result: 356 tests passed, but coverage correctly failed at 66.60%.

### GREEN

- Added deterministic tests for BrowserEngine lifecycle, Homepage extraction,
  ApplyFlow failures, Orchestrator coordination, auto login, application step
  handlers, and human-behavior simulation.
- Final command:
  `uv run pytest -m 'not e2e' --cov=src --cov-branch
  --cov-report=term-missing --cov-report=json:data/coverage.json`
- Coverage-development result: 408 passed, 1 skipped, 20 deselected at 82.49%.
- Final release-gate result after the CI contract was added:
  409 passed, 1 existing skip, 20 opt-in E2E tests deselected.
- Final line+branch coverage: 82.39%.

### Debugging evidence

- A persistent-context double initially failed to add newly created pages to its
  `pages` collection. Matching Playwright state behavior removed the false failure;
  production code was unchanged.
- A login double supplied only three selector results although the implementation
  queries four signals. Adding the Sign-in result removed the false failure.
- Resume handling correctly made two humanized clicks—resume selection and Next—so
  the test was corrected to assert both calls.
- Max-step ApplyFlow exhaustion lacked diagnostic evidence. The failing test proved
  `screenshot_path` was `None`; the implementation now captures and returns a
  diagnostic screenshot.
- The full gate exposed repeated SQLite `ResourceWarning` messages. Python's
  connection context commits or rolls back but does not close; wrapping the migration
  connection in `contextlib.closing` removed the leak while 19 database and
  coordination regression tests remained GREEN.

### Clean CI environment correction

The first GitHub Actions test job failed before collection because the clean
environment did not install `pytest-cov`, even though the inherited local virtual
environment already contained it. A CI contract assertion for the declared
`pytest-cov` development dependency reproduced the omission as RED. Adding
`pytest-cov>=7.0.0` to `.[dev]` and regenerating `uv.lock` made the contract GREEN;
privacy and lint jobs were already passing.

## Manual-only Checks

Live JobsDB login, CAPTCHA handling, JobsDB DOM changes, real Quick Apply submission,
macOS notifications and persistent Chromium profile reuse remain opt-in E2E checks.
They are intentionally excluded from CI because they require a real account, network,
interactive browser and private local state. Deterministic fakes cover the required
control-flow guarantees without exposing those resources.
